### Top-level call graph

- `validate`: `main` resolves `--repo`, then calls `validate_repository`. Validation loads the manifest, computes the exact expected `artefacts/` file set, checks catalogue-link cardinality, checks each HTML local reference and the cdnjs ban, and optionally invokes `git diff <base>...HEAD` for `HOMEPAGE_FILES` (`kevinlin.github.io/scripts/artefacts.py:1757-1823`; `kevinlin.github.io/scripts/artefacts.py:2273-2287`).
- `plan`: `main` first calls `read_head_manifest` through `git show HEAD:artefacts/manifest.json`, then calls `create_sync_plan`. The planner loads and normalizes the manifest, scans and filters the source, stops on approved unlisted files, drops entries with missing sources, builds all desired managed bytes, rewrites the existing catalogue shell, serializes the next manifest, prevalidates a temporary tree, classifies add/update/delete/orphan changes against disk and `HEAD`, and produces Markdown diffs. `main` prints `format_plan` and returns without applying (`kevinlin.github.io/scripts/artefacts.py:1909-1915`; `kevinlin.github.io/scripts/artefacts.py:1489-1593`; `kevinlin.github.io/scripts/artefacts.py:2299-2307`).
- `apply`: it executes the same plan path, prints the plan, then `confirm_and_apply` asks for literal `yes`. `apply_plan` writes add/update files atomically one at a time, deletes both `delete` and `orphan` paths, verifies every desired byte string and deletion, then `rebuild_showcase_atlas` may run a second site script (`kevinlin.github.io/scripts/artefacts.py:1657-1721`; `kevinlin.github.io/scripts/artefacts.py:2199-2205`; `kevinlin.github.io/scripts/artefacts.py:2299-2311`).
- `publish`: `main` calls `publish` directly. It checks installed `git`, `gh`, and `curl`, GitHub authentication, worktree shape, current branch `main`, and zero divergence from `origin/main`; computes and prints a plan; confirms; creates a timestamped branch; applies; rebuilds the atlas; runs the repository's unit test file and repository-local `scripts/artefacts.py validate --base-ref origin/main`; stages, commits, and pushes; opens a GitHub PR; waits for a check literally named `validate`; merges; restores local `main`; polls the Pages build for the merge commit; obtains the Pages URL; and curls the site root, catalogue, and every manifest-entry URL (`kevinlin.github.io/scripts/artefacts.py:1880-1906`; `kevinlin.github.io/scripts/artefacts.py:2041-2196`; `kevinlin.github.io/scripts/artefacts.py:2288-2298`).
- Unlisted-source exception path: all three mutating/plan commands can be diverted after scanning. `plan` prints a proposal and exits 3 without writing. `apply` and `publish` rescan, remove stale entries from the proposed manifest, derive additions, ask for confirmation, write only `artefacts/manifest.json`, and exit 3. A second invocation is required to sync or publish the bytes (`kevinlin.github.io/scripts/artefacts.py:2208-2247`; `kevinlin.github.io/scripts/artefacts.py:2312-2326`; `kevinlin.github.io/tests/test_artefacts.py:1877-1903`; `kevinlin.github.io/tests/test_artefacts.py:1952-1960`).

### Coupling the requirement missed

- Default topology is site-specific. The repo default is the parent of the script, which only works because the script is installed inside this site repo. The source default is exactly `~/Downloads/Artefacts`. The parser injects both defaults into `plan`, `apply`, and `publish` (`kevinlin.github.io/scripts/artefacts.py:2250-2269`).
- The destination tree name and control-file locations are repeated literals: `artefacts/manifest.json`, `artefacts/index.html`, the `artefacts` git pathspec, and the public `/artefacts/` URL. The target keeps this tree name, so these can be literals that move, but they are still topology assumptions rather than generic path handling (`kevinlin.github.io/scripts/artefacts.py:1504-1516`; `kevinlin.github.io/scripts/artefacts.py:1757-1766`; `kevinlin.github.io/scripts/artefacts.py:1909-1915`; `kevinlin.github.io/scripts/artefacts.py:2005-2012`; `kevinlin.github.io/scripts/artefacts.py:2085-2093`).
- A catalogue shell must already exist. `create_sync_plan` opens `artefacts/index.html` and fails if it cannot read it or find exactly one marker pair. There is no standalone catalogue template and no initialization path (`kevinlin.github.io/scripts/artefacts.py:1380-1391`; `kevinlin.github.io/scripts/artefacts.py:1504-1515`).
- The 3D showcase is wired into core apply and publish through `ATLAS_SCRIPT` and `ATLAS_OUTPUT`. If `showcase/atlas.js` is protected, every apply invokes `scripts/build_showcase_atlas.py`; the live manifest protects the showcase HTML, JPG, and JS (`kevinlin.github.io/scripts/artefacts.py:34-36`; `kevinlin.github.io/scripts/artefacts.py:1851-1868`; `kevinlin.github.io/scripts/artefacts.py:2070-2072`; `kevinlin.github.io/scripts/artefacts.py:2199-2205`; `kevinlin.github.io/artefacts/manifest.json:9-11`).
- Proposal taxonomy has personal-site literals: `Presentations and analysis`, `Image collections`, and `TODO: describe this collection.` They are used whenever the existing manifest cannot teach the proposal a section (`kevinlin.github.io/scripts/artefacts.py:913-916`; `kevinlin.github.io/scripts/artefacts.py:982-997`; `kevinlin.github.io/scripts/artefacts.py:1075-1104`).
- The transformation security policy singles out cdnjs. Proposal logic searches cdnjs URLs and matches their basename against protected files; transform and validation reject any surviving textual cdnjs reference, while other remote script hosts are allowed (`kevinlin.github.io/scripts/artefacts.py:29-40`; `kevinlin.github.io/scripts/artefacts.py:1000-1037`; `kevinlin.github.io/scripts/artefacts.py:1223-1244`; `kevinlin.github.io/scripts/artefacts.py:1790-1807`).
- The current approved file policy is hardcoded to `.html`, `.md`, `.png`, `.jpeg`, `.jpg`, and `.ico`, with lowercase-kebab public components and `.DS_Store` as the only ignored metadata filename. This is not the requirement's larger allowlist (`kevinlin.github.io/scripts/artefacts.py:23-30`; `kevinlin.github.io/scripts/artefacts.py:369-391`; `kevinlin.github.io/scripts/artefacts.py:454-485`; `docs/specs/requirement_artefact-sync.md:78-86`).
- The temporary plan validator assumes published pages are self-contained inside `artefacts/`, apart from three copied root homepage files. It does not copy arbitrary existing destination-repo assets, so an otherwise valid local reference to a shared root asset can fail the plan's temporary validation (`kevinlin.github.io/scripts/artefacts.py:1436-1461`; `kevinlin.github.io/scripts/artefacts.py:1738-1754`).
- Catalogue dates are not manifest data. They come from the local source file's `st_mtime` converted through the machine's local date, and a re-downloaded unchanged source deliberately changes the card date and order (`kevinlin.github.io/scripts/artefacts.py:1286-1304`; `kevinlin.github.io/scripts/artefacts.py:1322-1362`).
- Publishing is GitHub-specific far beyond Pages waiting and URL derivation. It requires `gh auth`, creates and merges a PR, polls a check named `validate`, queries repository identity, and calls GitHub Pages APIs (`kevinlin.github.io/scripts/artefacts.py:1880-1906`; `kevinlin.github.io/scripts/artefacts.py:1918-1980`; `kevinlin.github.io/scripts/artefacts.py:2120-2189`).

It executes `tests/test_artefacts.py` and `scripts/artefacts.py` relative to the destination repo, and then waits for the destination repo's `validate` workflow. The target explicitly says the destination receives no code and no CI (`kevinlin.github.io/scripts/artefacts.py:2073-2083`; `kevinlin.github.io/scripts/artefacts.py:1933-1955`; `kevinlin.github.io/.github/workflows/validate-artefacts.yml:3-25`; `docs/specs/requirement_artefact-sync.md:23-32`).
- Publish also contains site-specific messages and scope. Its PR body hardcodes the six current extensions, its branch and commit names are fixed, and it allows exactly one pre-existing worktree edit, an unstaged `artefacts/manifest.json` (`kevinlin.github.io/scripts/artefacts.py:1885-1892`; `kevinlin.github.io/scripts/artefacts.py:2068-2069`; `kevinlin.github.io/scripts/artefacts.py:2095-2119`).

## Section 3 - Extraction seams

The natural seam is not a line-by-line parameterization of the monolith. It is a small pure core around manifest, scan, transform, plan, apply, and validate, with path/config resolution before that core and publish orchestration after it. The existing core already passes `repo_root`, `source_root`, and `artefacts_root` through its main planning functions, so it does not fundamentally depend on process cwd once those roots are supplied (`kevinlin.github.io/scripts/artefacts.py:1247-1277`; `kevinlin.github.io/scripts/artefacts.py:1489-1593`; `kevinlin.github.io/scripts/artefacts.py:1690-1721`).

### Classification of coupled pieces

| Class | Coupled pieces | Boundary |
|---|---|---|
| (a) Plain config with neutral defaults | User pointer `{repo, source}`; branch and remote names; direct-push versus protected-branch mode; favicon; Markdown page shell; standalone catalogue shell versus a configured host page; marker strings if they are made customizable; approved extensions; optional public base-URL override; and any optional changed-path guard. The requirement needs config beyond the one-line pointer but does not say where it lives (`docs/specs/requirement_artefact-sync.md:23-45`; `docs/specs/requirement_artefact-sync.md:64-86`; `docs/specs/requirement_artefact-sync.md:107-112`). | Resolve once before dispatch. Pass a value object into high-level plan/validate/publish functions rather than letting leaf functions discover home, cwd, or the script location. |
| (b) Provider hook | First, derive or verify the public base URL from the git remote. Second, wait until the host has deployed the pushed commit. These map to the current GitHub URL query and `_wait_for_pages`, but not to current PR/check creation (`kevinlin.github.io/scripts/artefacts.py:1958-1980`; `kevinlin.github.io/scripts/artefacts.py:2167-2189`; `docs/specs/requirement_artefact-sync.md:107-112`). | Provider input is remote/repository plus commit; provider output is a base URL or successful deployment observation. All scan/sync/git operations remain provider-free. |
| (c) Literal that moves | The fixed `artefacts/manifest.json` topology, manifest version 1, Markdown block markers and reversible escaping, default catalogue markers, change kinds, the stdlib command runner, and neutral default HTML/catalogue templates can stay literals in the skill package (`kevinlin.github.io/scripts/artefacts.py:25-32`; `kevinlin.github.io/scripts/artefacts.py:80-99`; `kevinlin.github.io/scripts/artefacts.py:525-562`; `kevinlin.github.io/scripts/artefacts.py:1394-1433`). | Move with the code. Do not expose values as config unless the requirement needs user choice. |
| Remove instead of classifying | Exact `kevinlin.github.io` pruning, homepage guard defaults, showcase atlas integration, Kevin-branded template content, cdnjs-only policy, site taxonomy defaults, and current always-PR/check workflow are live site behavior but not portable core behavior (`kevinlin.github.io/scripts/artefacts.py:447-485`; `kevinlin.github.io/scripts/artefacts.py:913-916`; `kevinlin.github.io/scripts/artefacts.py:1851-1980`). | Delete or replace with the neutral behavior named in the requirement. Do not create generic hook systems for one removed site feature. |

The provider boundary can remain only two hooks if protected-branch mode means git pushes a branch and the tool stops with instructions. If the tool itself must create, monitor, and merge a PR, then the requirement's two-hook provider claim is false because plain git cannot perform those operations; current code uses four separate `gh pr` operations plus check polling (`kevinlin.github.io/scripts/artefacts.py:1924-1955`; `kevinlin.github.io/scripts/artefacts.py:2123-2163`; `docs/specs/requirement_artefact-sync.md:44-45`; `docs/specs/requirement_artefact-sync.md:107-112`).

### Functions whose boundary or signature must change

These are the functions that currently consume a site/config global, embed a destination-repo path/branch assumption, or rely on the script being co-located with the repo. Constants that are stable format internals, such as Markdown escaping markers, can move unchanged and do not require signature changes.

- Manifest and inventory policy: `has_cdnjs_reference`, `validate_manifest`, and `scan_source` currently read the cdnjs, extension, path-pattern, metadata, or site-dir globals. `suggest_destination` also reads the generated-page extension policy (`kevinlin.github.io/scripts/artefacts.py:23-40`; `kevinlin.github.io/scripts/artefacts.py:335-392`; `kevinlin.github.io/scripts/artefacts.py:447-485`; `kevinlin.github.io/scripts/artefacts.py:897-910`).
- Rendering and proposal: `markdown_vendor_path`, `render_markdown_page`, `_vendor_replacements`, `propose_manifest_additions`, `ensure_favicon`, `transform_html`, and `build_desired_files` consume the hardcoded parser basename, template/favicon, cdnjs policy, section defaults, and generated-page policy (`kevinlin.github.io/scripts/artefacts.py:808-850`; `kevinlin.github.io/scripts/artefacts.py:1000-1146`; `kevinlin.github.io/scripts/artefacts.py:1208-1277`).
- Catalogue and planning: `collect_source_timestamps` should disappear if `date` becomes manifest data; `render_catalogue` must consume the new entry fields rather than a runtime timestamp side table; `_validate_desired_tree`, `create_sync_plan`, and `format_plan` need catalogue-mode, validation-scope, public-URL, and byte-size context (`kevinlin.github.io/scripts/artefacts.py:1286-1377`; `kevinlin.github.io/scripts/artefacts.py:1436-1519`; `kevinlin.github.io/scripts/artefacts.py:1596-1654`). `replace_generated_catalogue` needs a marker argument only if markers are configurable; fixed default markers can remain a literal (`kevinlin.github.io/scripts/artefacts.py:1380-1391`).
- Repository validation: `validate_repository` needs resolved topology/policy rather than hardcoded `artefacts/`, cdnjs, and `HOMEPAGE_FILES` behavior (`kevinlin.github.io/scripts/artefacts.py:1757-1823`).
- Publish: `_publish_preflight`, `_wait_for_pages`, `_public_urls`, and `publish` need branch/remote/strategy/provider inputs and skill-owned test locations. `_require_successful_checks` and `_restore_main` belong only to the old PR workflow and should be removed unless protected-branch behavior is specified to retain them (`kevinlin.github.io/scripts/artefacts.py:1880-2012`; `kevinlin.github.io/scripts/artefacts.py:2041-2196`).
- Entry and dispatch: `default_repo_root` and `default_source_root` must be replaced by pointer loading. `_parser` and `main` must resolve that pointer before dispatch; explicit overrides can still be accepted, but the default cannot be derived from the skill script's parent (`kevinlin.github.io/scripts/artefacts.py:2250-2304`; `docs/specs/requirement_artefact-sync.md:23-32`).
- Site-only removal changes callers rather than signatures: remove `rebuild_showcase_atlas` and its calls from `confirm_and_apply` and `publish` (`kevinlin.github.io/scripts/artefacts.py:1851-1868`; `kevinlin.github.io/scripts/artefacts.py:2070-2072`; `kevinlin.github.io/scripts/artefacts.py:2199-2205`).

Functions already on a sound portable seam include `_resolve_within`, manifest JSON parsing/serialization after the model is updated, order normalization, ignore matching, Markdown escape/unescape/extract, `markdown_diff`, `drop_entries_without_source`, `reconcile_inventory`, `public_href`, published-tree scanning, unexpected-file set subtraction, atomic write, destination containment, and the command-runner abstraction. Their inputs already carry the state they need (`kevinlin.github.io/scripts/artefacts.py:84-99`; `kevinlin.github.io/scripts/artefacts.py:395-444`; `kevinlin.github.io/scripts/artefacts.py:488-516`; `kevinlin.github.io/scripts/artefacts.py:525-562`; `kevinlin.github.io/scripts/artefacts.py:1182-1205`; `kevinlin.github.io/scripts/artefacts.py:1464-1486`; `kevinlin.github.io/scripts/artefacts.py:1657-1687`; `kevinlin.github.io/scripts/artefacts.py:1826-1848`).

## Section 4 - Do-not-port list

No clearly dead core algorithm was found. The items below are exercised by current code or tests, but are site-only or incompatible with the agreed topology.

- Do not port `rebuild_showcase_atlas` or its `ATLAS_*` trigger. It exists solely to regenerate a 3D gallery's protected outputs, is not represented in `SyncPlan`, and invokes a second repo-local script (`kevinlin.github.io/scripts/artefacts.py:34-36`; `kevinlin.github.io/scripts/artefacts.py:1851-1868`; `kevinlin.github.io/tests/test_artefacts.py:1663-1693`).
- Do not port `build_showcase_atlas.py`. It packs this site's published images into a 512-pixel-cell JPEG/JavaScript texture atlas for one WebGL showcase, depends on `ffmpeg` and `ffprobe`, and writes `artefacts/showcase/atlas.jpg` plus `atlas.js`. It is a consumer-specific post-process, not a general artefact sync responsibility (`kevinlin.github.io/scripts/build_showcase_atlas.py:2-25`; `kevinlin.github.io/scripts/build_showcase_atlas.py:38-40`; `kevinlin.github.io/scripts/build_showcase_atlas.py:127-163`).
- Do not port the exact `kevinlin.github.io` directory-name exclusion. Exclude the resolved destination repo when necessary, rather than a public user's arbitrary folder with the same basename (`kevinlin.github.io/scripts/artefacts.py:454-464`).
- Do not port `HOMEPAGE_FILES` as a default invariant. It enforces this site's PR separation and copies an incomplete subset of root files into plan validation. A portable sync should validate the configured managed/catalogue scope (`kevinlin.github.io/scripts/artefacts.py:33-36`; `kevinlin.github.io/scripts/artefacts.py:1436-1461`; `kevinlin.github.io/scripts/artefacts.py:1809-1818`).

## Section 7 - Contradictions and risks

- **The Markdown invariant is text-round-trip exact only under conditions, not byte-exact for every input.** Rendering rejects non-UTF-8 bytes and appends a final newline when one is absent, then encodes UTF-8 again. Escape/unescape is exact for the resulting text, including script/comment markers and trailing spaces, but the original byte sequence is changed for a valid UTF-8 file without a final newline (`kevinlin.github.io/scripts/artefacts.py:528-562`; `kevinlin.github.io/scripts/artefacts.py:817-850`; `kevinlin.github.io/tests/test_artefacts.py:962-985`; `kevinlin.github.io/tests/test_artefacts.py:1011-1014`). No test covers a Markdown source missing its final newline. Also, `apply_plan` verifies the rendered destination bytes against the already computed rendered bytes; it never extracts Markdown and compares that extraction with the source. The round trip supports diffing and browser rendering, not apply's post-write check (`kevinlin.github.io/scripts/artefacts.py:856-894`; `kevinlin.github.io/scripts/artefacts.py:1713-1721`; `docs/specs/requirement_artefact-sync.md:64-69`).
- **`destination` is not frozen.** Manifest validation checks uniqueness, shape, extension, and collection membership, but never compares an existing entry's destination to `HEAD`. The planner explicitly treats a destination edit as add-new plus delete-old, and a test proves that behavior (`kevinlin.github.io/scripts/artefacts.py:335-392`; `kevinlin.github.io/scripts/artefacts.py:1538-1556`; `kevinlin.github.io/tests/test_artefacts.py:1467-1484`; `docs/specs/requirement_artefact-sync.md:58-60`).
- **Source rename preservation is heuristic, not an invariant.** Unlisted handling drops every entry whose old source disappeared, then derives a fresh destination from the new source. The passing rename test changes `Doc.md` to `Doc.html`, so the stem-derived destination coincidentally stays `charts/doc/index.html`. A rename such as `Deploy Flow.png` to `Deploy Flow v3.png` derives a new public path and loses the old destination unless a human edits the proposal (`kevinlin.github.io/scripts/artefacts.py:904-910`; `kevinlin.github.io/scripts/artefacts.py:1107-1141`; `kevinlin.github.io/scripts/artefacts.py:2222-2242`; `kevinlin.github.io/tests/test_artefacts.py:1905-1941`).
- **`replacements` is broader and harsher than the requirement implies.** It is an ordered raw-text replacement map applied only to HTML. Each key must occur at least once or the run fails; every occurrence is replaced; later mappings see text produced by earlier mappings. The same transform then strips trailing spaces, injects the favicon, and rejects surviving cdnjs. Proposal auto-fill understands only cdnjs URLs whose final filename matches a protected vendor basename (`kevinlin.github.io/scripts/artefacts.py:276-296`; `kevinlin.github.io/scripts/artefacts.py:1011-1037`; `kevinlin.github.io/scripts/artefacts.py:1223-1244`; `docs/specs/requirement_artefact-sync.md:47-56`). It is not specifically an absolute-path facility, and no replacement is applied to Markdown or binary sources (`kevinlin.github.io/scripts/artefacts.py:1247-1276`).
- **Full workflow convergence is not established.** Managed add/update files are individually atomic, and rerunning can repair a partial managed-tree apply. But catalogue bytes also depend on source mtimes and an existing shell, protected files are external state, and the atlas mutates protected outputs after `apply_plan` outside `SyncPlan` (`kevinlin.github.io/scripts/artefacts.py:1286-1304`; `kevinlin.github.io/scripts/artefacts.py:1436-1461`; `kevinlin.github.io/scripts/artefacts.py:1673-1721`; `kevinlin.github.io/scripts/artefacts.py:1851-1868`). If publish applies successfully and atlas rebuilding fails, the immediate rerun is rejected because the first run already switched away from `main` and dirtied more than the one worktree path preflight permits. Even after manual branch/worktree recovery, a state with no managed changes returns before rebuilding the atlas. That recovery path is not convergent without operator action (`kevinlin.github.io/scripts/artefacts.py:1885-1906`; `kevinlin.github.io/scripts/artefacts.py:2060-2072`; `kevinlin.github.io/tests/test_artefacts.py:1683-1693`; `docs/specs/requirement_artefact-sync.md:124-133`).
- **Orphan behavior directly conflicts with the requirement.** Current `DELETION_KINDS` contains both `delete` and `orphan`; `apply_plan` unlinks both; plan text labels orphans `Delete (orphaned)`; tests prove an orphan-only publish deletes the file. The requirement says orphans warn only (`kevinlin.github.io/scripts/artefacts.py:31-32`; `kevinlin.github.io/scripts/artefacts.py:1616-1633`; `kevinlin.github.io/scripts/artefacts.py:1697-1721`; `kevinlin.github.io/tests/test_artefacts.py:1624-1645`; `kevinlin.github.io/tests/test_artefacts.py:2340-2351`; `docs/specs/requirement_artefact-sync.md:88-98`).
- **Warn-only orphans also conflict with current validation.** `validate_repository` rejects every published file outside manifest destinations, protected files, the catalogue, and the manifest. If the replacement merely warns and leaves an orphan, its required local validate step will fail before publish unless validation also changes to report rather than reject orphans (`kevinlin.github.io/scripts/artefacts.py:1757-1778`; `docs/specs/requirement_artefact-sync.md:44-45`; `docs/specs/requirement_artefact-sync.md:93-95`).
- **The sample `CNAME` does not protect a repository-root custom-domain file.** Every `protected_files` path is resolved below `artefacts_root`, and orphan scanning is also limited to that tree. The sample's `"CNAME"` therefore means `artefacts/CNAME`, while the safety rationale discusses preserving the repo-root Pages `CNAME`, which current code never scans or deletes (`kevinlin.github.io/scripts/artefacts.py:1450-1475`; `kevinlin.github.io/scripts/artefacts.py:1757-1767`; `docs/specs/manifest.sample.json:4-8`; `docs/specs/requirement_artefact-sync.md:93-95`).
- **The closed allowlist does not stop on every unlisted source file.** It stops only for files whose suffix is already in `APPROVED_EXTENSIONS`. Other suffixes are silently excluded from reconciliation and merely summarized by suffix; `.DS_Store`, hidden directories, and manifest-ignored approved files also never enter the unlisted set (`kevinlin.github.io/scripts/artefacts.py:447-485`; `kevinlin.github.io/scripts/artefacts.py:496-516`; `kevinlin.github.io/scripts/artefacts.py:1194-1205`; `kevinlin.github.io/scripts/artefacts.py:1643-1654`; `docs/specs/requirement_artefact-sync.md:78-86`). The requirement's wording needs to distinguish unsupported, ignored, and approved-but-unlisted files.
- **The proposed seeded ignore patterns do not match the current ignore language.** Current rules are exact file matches or literal directory-prefix matches when ending in `/`; there is no glob engine. A seed such as `*.local.*` is treated as a literal filename and will match nothing, and “dotfiles” has no representable blanket rule (`kevinlin.github.io/scripts/artefacts.py:315-320`; `kevinlin.github.io/scripts/artefacts.py:488-516`; `docs/specs/requirement_artefact-sync.md:99-101`).
- **The sample's optional entry fields are not supported and will be discarded.** `Entry` has no `description` or `date`; `manifest_from_dict` ignores unknown entry keys; `manifest_to_json` emits only the old fields. Therefore a sync that rewrites the sample manifest loses both additions. Current catalogue date behavior instead reads local source mtime (`kevinlin.github.io/scripts/artefacts.py:112-120`; `kevinlin.github.io/scripts/artefacts.py:272-297`; `kevinlin.github.io/scripts/artefacts.py:1286-1304`; `kevinlin.github.io/scripts/artefacts.py:1410-1423`; `docs/specs/manifest.sample.json:45-67`; `docs/specs/requirement_artefact-sync.md:47-60`).
- **“Destination repo holds only the manifest” conflicts with Markdown and protected-file validation.** Publishing Markdown requires a protected file whose basename is `marked.min.js`, and planned-tree validation fails if every protected file is not already present and non-symlinked in the destination repo. The sample also protects Chart.js and `CNAME`, but the skill topology specifies no asset provisioning mechanism (`kevinlin.github.io/scripts/artefacts.py:808-814`; `kevinlin.github.io/scripts/artefacts.py:1268-1273`; `kevinlin.github.io/scripts/artefacts.py:1450-1456`; `docs/specs/manifest.sample.json:4-8`; `docs/specs/requirement_artefact-sync.md:23-32`). This must be resolved before extraction: bundle/copy assets, permit generated protected assets, or require them as repo-owned inputs.
- **Standalone catalogue generation does not exist.** The planner cannot run in a repo containing only a manifest because it must first read a marker-bearing `artefacts/index.html`. The requirement promises to generate a standalone index by default but defines neither its storage/config nor how `init` creates it (`kevinlin.github.io/scripts/artefacts.py:1380-1391`; `kevinlin.github.io/scripts/artefacts.py:1504-1516`; `docs/specs/requirement_artefact-sync.md:23-32`; `docs/specs/requirement_artefact-sync.md:71-76`).
- **Current publish cannot be lifted into the stated topology.** It runs tests and the validate CLI from destination-repo paths, then requires a destination-repo CI check named `validate`, while the target installs neither code nor CI there. It also always PR-merges rather than pushing directly to main (`kevinlin.github.io/scripts/artefacts.py:1933-1955`; `kevinlin.github.io/scripts/artefacts.py:2073-2083`; `kevinlin.github.io/scripts/artefacts.py:2123-2165`; `docs/specs/requirement_artefact-sync.md:23-45`). Skill-owned tests can test the tool, but the requirement must say what repository-specific tests, if any, `publish` should discover and run.
- **The two-hook provider layer is incompatible with automated protected-branch PRs.** Deriving a URL and waiting for Pages are sufficient for direct git push. They are not sufficient to create, inspect, and merge a PR or wait for host checks, which current code does through `gh`. Either protected-branch mode stops after branch push, or the provider surface must grow (`kevinlin.github.io/scripts/artefacts.py:1918-1955`; `kevinlin.github.io/scripts/artefacts.py:2123-2163`; `docs/specs/requirement_artefact-sync.md:44-45`; `docs/specs/requirement_artefact-sync.md:107-112`).
- **The new `plan` safety contract has almost no data foundation.** Current `Change` stores no source, byte size, or public URL; `format_plan` groups by operation; there are no secret-shape or sensitive-name checks. Implementing consequence groups, full URLs, add sizes, and warnings is new behavior, not extraction (`kevinlin.github.io/scripts/artefacts.py:154-169`; `kevinlin.github.io/scripts/artefacts.py:1616-1654`; `docs/specs/requirement_artefact-sync.md:88-103`).
- **The new file-type contract is new implementation.** Current code rejects `.pdf`, `.webp`, `.gif`, and `.svg`. There is no SVG parser or sanitizer and no tests for those formats. Adding the three binary types is small; safe SVG sanitization is a separate security feature and is not supported by the stdlib HTML transformation path (`kevinlin.github.io/scripts/artefacts.py:25-26`; `kevinlin.github.io/scripts/artefacts.py:369-387`; `kevinlin.github.io/tests/test_artefacts.py:150-168`; `docs/specs/requirement_artefact-sync.md:78-84`).
- **`init`, user-pointer lookup, and `add` are wholly new.** The parser has no such commands, no user config path, and no copy operation. Current explicit `--repo`/`--source` flags make invocations cwd-independent only when the caller supplies them; after extraction, the script-parent default points to the skill directory rather than the destination repo (`kevinlin.github.io/scripts/artefacts.py:2250-2270`; `docs/specs/requirement_artefact-sync.md:23-43`).
- **“Fetch every published URL” is stronger than current proof.** `_public_urls` checks the site root, the artefacts catalogue, and entry URLs, but omits all protected files. The live protected set includes the showcase and vendor assets, so current success does not prove every published file is reachable (`kevinlin.github.io/scripts/artefacts.py:2005-2038`; `kevinlin.github.io/artefacts/manifest.json:3-39`; `docs/specs/requirement_artefact-sync.md:40-45`).
- **Remote dependency validation is not a general publication safety gate.** `_resolve_local_reference` deliberately skips every URL with a scheme or host, and validation only adds a textual exception for cdnjs. An HTML artefact can publish scripts, images, or styles from any other remote host without a warning or reachability check (`kevinlin.github.io/scripts/artefacts.py:1738-1754`; `kevinlin.github.io/scripts/artefacts.py:1790-1807`). The replacement design should state whether that is accepted behavior.
- **Separated `sync` and `publish` conflict with current worktree preflight.** Current publish accepts a clean tree or one unstaged manifest edit only. If the new `sync` command leaves generated artefact changes in the destination worktree for a later `publish`, the existing preflight rejects the normal workflow. The replacement must decide whether `publish` always recomputes/applies sync itself or publishes an already-synced working tree (`kevinlin.github.io/scripts/artefacts.py:1885-1892`; `kevinlin.github.io/scripts/artefacts.py:2049-2072`; `docs/specs/requirement_artefact-sync.md:36-45`).
- **Real end-to-end publication remains unproven.** The publish suite replaces every command, Pages response, and HTTP response with `RecordingRunner`; only the requirement calls for a disposable real Pages repository. The current tests are strong orchestration unit tests, not evidence that auth, push, build timing, URL derivation, or deletion works on a live host (`kevinlin.github.io/tests/test_artefacts.py:2124-2197`; `kevinlin.github.io/tests/test_artefacts.py:2249-2506`; `docs/specs/requirement_artefact-sync.md:118-122`).

## Lessons learned

- The portable core is real, but the site-specific surface is materially larger than seven literals.
